## วิธีวิจัยโดยย่อ

ใช้ภาพ RWS ของ Pamela Colman Smith ควบคู่กับคำอธิบายและรายการความหมายใน *The Pictorial Key to the Tarot* ของ A. E. Waite แล้วเปิดบทสอนรายใบของ Joan Bunning เทียบครบ 78 ใบ ข้อความ Wikisource ที่ใช้ระบุฉบับพิมพ์ซ้ำ 1922 จึงไม่ใช้ปีนี้เป็นปีสร้างไพ่ ภาพและความหมายเป็นหลักฐานเกี่ยวกับประเพณีการตีความ ไม่ใช่หลักฐานยืนยันความสามารถทำนายอนาคต [W-P2, W-P3; JB-*]

Waite และ Bunning เป็นผู้เขียนคนละคน แต่สืบประเพณี RWS ร่วมกัน จึงไม่อ้างว่าเป็นหลักฐานอิสระเชิงทดลอง ไม่มีการเพิ่มโหราศาสตร์ เลขศาสตร์ ธาตุ หรือสำนักอื่นเพื่อทำข้อมูลให้ดูครบ ไม่มีบริบทสุขภาพ สีมงคล เวลามงคล เลขนำโชค มนต์ หรือคำทำนายพนัน

อ่านข้อความกลับหัวของ Waite เป็นรายใบและใช้บทเรียนกลับหัวของ Bunning เป็นกรอบประกอบเท่านั้น บทเรียนทั่วไปไม่ใช่บทกลับหัวเฉพาะ 78 ใบ ความหมายภาษาไทยทั้งหมดเรียบเรียงใหม่; คำอ่าน 6 บริบทเป็นการประยุกต์ของบรรณาธิการ ไม่ใช่การแปลคำทำนายเชิงพาณิชย์

## หลักฐานสามระดับ

- `source_supported`: รายงานชื่อหรือสิ่งที่เห็น/อ่านได้จากแหล่งเฉพาะ ไม่ได้แปลว่าคำพยากรณ์เป็นความจริง
- `editorial_synthesis`: ย่อ ผสาน เลือกน้ำหนัก หรือประยุกต์ให้เป็นภาษาไทยและคำแนะนำตามบริบท ไม่อ้างว่าผู้เขียนต้นทางกล่าวข้อความนั้นโดยตรง
- `disputed`: บันทึกจุดที่ข้อความต่างส่วน ผู้เขียน หรือข้อความกับภาพให้น้ำหนัก/รายละเอียดต่างกัน โดยบอกว่าต่างตรงไหน ไม่ติดป้ายนี้กับทุกความหมายกลับหัวที่บรรณาธิการแต่งต่างจากตำรา

`evidence[].field_path` เป็น JSON Pointer เช่น `/contexts/daily/reading` และ `/symbolism/0/observation` ส่วน `source_ids` เชื่อมกับ `sources.json` ชื่อไทยเป็นทางเลือกบรรณาธิการจึงอาจมี `source_ids: []`; ไม่สร้างแหล่งปลอมเพื่อเติมช่องนี้ การไม่มีแหล่งตรงไม่เท่ากับการละเว้นป้ายหลักฐาน

`source_comparison` แยกบันทึก Waite, Bunning และทางเลือกกลับหัว บันทึกเหล่านี้มีทั้งสาระจากแหล่งและนโยบายตัดข้อความที่ไม่เหมาะ จึงติดป้าย `editorial_synthesis` แทนกล่าวว่าทุกคำเป็นข้อความตรงจากตำรา จุดขัดแย้งที่ระบุชัดแยกอยู่ใน `disagreement`

## ข้อมูลและการเชื่อมระบบ

| Field | ความหมาย / รูปแบบ |
|---|---|
| `legacy_id` | รหัสเชื่อมระบบตามโจทย์ ห้ามแก้สะกด |
| `name_en`, `name_th` | ชื่อแสดงผล; ชื่อไทยเป็นตัวเลือกฉบับนี้ ไม่ได้ยืนยันตรงกับ CMS เก่า |
| `arcana` | `major` หรือ `minor` |
| `suit` | `wands`, `cups`, `swords`, `pentacles`; Major เป็น null |
| `rank` | ชื่ออันดับภาษาอังกฤษมาตรฐาน; Major เป็น null |
| `rank_key` | การสะกด legacy เช่น `fives`, `sixs`, `pages`; Major เป็น null |
| `number` | Major 0–21; Minor หนึ่งถึงสิบใช้ 1–10; Court เป็น null ไม่สร้างเลขพิมพ์บนไพ่ |
| `rank_order` | อันดับภายในชุด Minor 1–14 ใช้เรียงข้อมูล ไม่ใช่เลขศาสตร์ |
| `order` | ลำดับ 0–77: Major → Wands → Cups → Swords → Pentacles |
| `keywords` | 3–5 คำสำคัญ |
| `summary`, `upright`, `reversed` | ข้อความภาษาไทยสำหรับสารานุกรม |
| `symbolism` | 2–4 จุด แยก motif, observation, interpretation |
| `contexts` | daily, monthly, love, money, career, luck; รอบนี้ตั้งตรงเท่านั้น |
| `reading_sentences` | สองประโยคที่เขียนแยกไว้เพื่อช่วยตรวจโครงสร้างภาษาไทย; `reading` รวมด้วยเว้นวรรค |
| `advice`, `caution` | อย่างละหนึ่งประโยคปฏิบัติได้; ไม่เป็นรายการหลายข้อ |
| `differentiation` | ไพ่ใกล้เคียง 1–2 ใบ โดยอ้าง legacy_id และอธิบายความต่าง |
| `research_audit` | ระบุการอ่านรายใบ ขอบเขตตรวจภาพ และสิ่งที่ยังไม่ตรวจ |
| `research_status` | `researched` หรือ `researched_with_visual_gap` |
| `publication_readiness` | ทุก record เป็น `editorial_review`; ไม่มี `approved` |

`manifest.csv` เป็น UTF-8 พร้อม BOM เพื่อเปิดชื่อไทยในโปรแกรมตารางได้สะดวก; JSON/NDJSON/Markdown เป็น UTF-8 ไม่มี BOM ทุก record มีโครงสร้างเดียวกัน ใช้ null เมื่อ field ไม่เกี่ยวข้อง ไม่ใช่ placeholder เนื้อหาที่ขาด

รหัส Major ใช้ข้อยกเว้น `temperance` และ `the-judgment` แม้ชื่อแสดงผลเป็น `Judgement` ส่วน Minor คง `fives`, `sixs`, `sevens`, `eights`, `nines`, `tens`, `pages`, `knights`, `queens`, `kings` ตามคำสั่ง ไฟล์ manifest เดิมฉบับเต็มไม่ได้แนบ/กู้คืนเป็นไฟล์ต้นฉบับได้ในรอบนี้; มีเพียงรายงานเดิมที่ยืนยันรูปแบบบางส่วน จึงสร้าง manifest ตามโจทย์ปัจจุบัน ไม่อ้างว่าตรวจเทียบฐาน CMS สดแล้ว

## ขอบเขตที่ยังเปิด

เนื้อหาครบ แต่การตรวจภาพจริงมีช่องว่าง 7 ใบ: ห้าไม้เท้า เจ็ดไม้เท้า สิบไม้เท้า สี่ดาบ เจ็ดดาบ แปดดาบ และสิบดาบ มีคำบรรยายจาก Waite เป็นฐานแทนและระบุรายใบไว้ ไม่แจกภาพที่นำมาใช้ตรวจ; ต้องตรวจสิทธิ์ฉบับภาพก่อนใช้ production

ยังไม่มีผู้เชี่ยวชาญหรือบรรณาธิการภาษาไทยอีกคนอนุมัติ ไม่มีการเปรียบเทียบ manifest/schema กับระบบสด ไม่มีการนำเข้า CMS แก้โค้ด เปลี่ยนกลไกสุ่ม หรือ deploy รายละเอียดและคำสั่งตรวจต่ออยู่ใน `quality-report.md`
