# Prompt สำหรับให้ ChatGPT วิเคราะห์และ redesign มงคลเวลา

วันที่จัดทำ: 20 กันยายน 2026

## วิธีใช้

แนบ `02-PAGE-CONTEXT-AND-DATA.md`, `03-BRANDING-AND-CI.md` และภาพที่เกี่ยวข้องจาก `assets/` พร้อมข้อความใต้หัวข้อ “Prompt พร้อมใช้” ด้านล่าง เอกสารทั้งสองอ่านได้โดยไม่ต้องเข้าถึง codebase

ไฟล์ภาพแยกหน้าชัดเจน:

- `home-production-desktop.png`: ภาพแบ่งช่วงของ Home จริง `/` จาก production วันที่จัดทำ
- `temple-hub-user-reference.png`: ภาพที่เจ้าของส่งมา เป็นหน้า `/temples/` ไม่ใช่ `/`
- ไฟล์ `mongkolwela-*` ใน assets คือโลโก้จริงสำหรับใช้อ้างอิง

เว็บไซต์อาจจำกัด automated browsing หากเปิดไม่ได้ ให้ใช้เอกสารและภาพแนบ และระบุข้อจำกัด อย่าอ้างว่าได้ทดสอบหน้าเว็บที่เปิดไม่ได้

## Prompt พร้อมใช้

คุณเป็น Senior Product Designer, UX Strategist และ Brand Designer ที่เข้าใจเว็บไซต์ภาษาไทย การค้นหาสถานที่ และเครื่องมือวางแผนเดินทาง

ช่วยวิเคราะห์และเสนอ redesign เว็บไซต์ “มงคลเวลา / Mongkol Wela” โดยอ่านเอกสารบริบทและ branding/CI ที่แนบให้ครบก่อน อย่าเริ่มจาก template เว็บไซต์ทั่วไป

### เป้าหมายและขอบเขต

เว็บไซต์: https://mongkolwela.vercel.app/

งานหลักคือวิเคราะห์หน้า Home `/` เพื่อพาคนจากความตั้งใจไปสู่การค้นหาสถานที่และวางแผนไหว้พระได้ง่ายขึ้น ภาพแนบที่ขึ้นหัวข้อ “วัดดังเสริมมงคล” คือหน้า Temple Hub `/temples/` ให้พิจารณาความสัมพันธ์ของสองหน้าและเสนอว่าแต่ละหน้าควรทำหน้าที่ต่างกันอย่างไร โดยยังคงทั้งสอง URL ไว้

หากฉันระบุภายหลังว่าให้ออกแบบตามภาพ “วัดดังเสริมมงคล” ให้เปลี่ยนหน้าหลักของงานเป็น `/temples/` และใช้ Home เป็นบริบท ห้ามปะปนโครงสร้างสองหน้าจนเสนอหน้าที่ไม่มีอยู่จริง

เว็บนี้เป็นคู่มือค้นหาวัด สถานที่ศักดิ์สิทธิ์ และสถานที่มงคล พร้อมเครื่องมือวางแผนไหว้พระ 3 / 5 / 9 แห่ง จุดขายคือการนำข้อมูลสถานที่มาช่วยจัดลำดับการเดินทาง มีพิกัด ข้อมูลเข้าชมและการเดินทางที่ต้องตรวจสอบตามความพร้อมของแต่ละรายการ ปฏิทินไทยและเครื่องมืออื่นเป็นส่วนเสริม ไม่ควรเปลี่ยน positioning ให้กลายเป็นเว็บดูดวงหลัก

ผู้ใช้ควรเริ่มได้ทั้งจาก “รู้ชื่อสถานที่แล้ว”, “รู้จังหวัดที่จะไป”, “รู้เรื่องที่อยากขอพรแต่ไม่รู้จะไปไหน” และ “อยากให้ระบบจัดทริป” กลุ่มนี้เป็นโจทย์การใช้งานจาก product ไม่ใช่ personas ที่ผ่านงานวิจัยแล้ว

### สิ่งที่อยากให้คุณวิเคราะห์

1. อธิบายก่อนว่าคุณเข้าใจบทบาทของ Home และ Temple Hub อย่างไร พร้อมชี้ส่วนที่ซ้ำหรือทำให้ผู้ใช้ต้องคิดมาก
2. วิเคราะห์ hierarchy, CTA, การค้นหา, ความชัดเจนของจุดขาย planner, จำนวนทางเลือก, ภาพและข้อความ, ความยาวหน้า, ความน่าเชื่อถือ และการใช้งานบนมือถือ
3. ทำตารางทุก section: เก็บ / ปรับ / ย้าย / รวม / ตัด / เพิ่ม พร้อมเหตุผลที่เชื่อมกับงานของผู้ใช้ ข้อแลกเปลี่ยน และผลต่อเส้นทางใช้งานเดิม
4. แยกสิ่งที่เห็นจากภาพหรือเอกสารจริง ออกจากข้อสันนิษฐานด้าน UX และสิ่งที่ต้องมีข้อมูลเพิ่ม อย่าแต่ง conversion rate, heatmap, คะแนนความพึงพอใจ หรือผล user research
5. เสนอแนวทางที่แตกต่างกัน 2 ทางอย่างกระชับ แล้วเลือกทางที่แนะนำพร้อมเหตุผล ไม่ต้องเสนอหลายสไตล์ที่ต่างกันแค่สี
6. วางโครงหน้าใหม่จากบนลงล่าง ระบุเป้าหมายแต่ละ section, headline/copy ภาษาไทย, CTA และปลายทางจริง รวมถึงสิ่งที่ผู้ใช้ควรเห็นใน viewport แรก
7. ระบุ mobile adaptation: ลำดับเนื้อหา การค้นหา เมนู ปุ่ม วัสดุภาพ และพื้นที่ที่ควรยุบหรือเลื่อน ไม่ใช่เพียงลดขนาด desktop
8. ส่ง design direction ที่นำไปออกแบบต่อได้: สีตามบทบาท ฟอนต์และ type hierarchy ความหนาแน่น grid/gutter การใช้ภาพ รูปแบบ cards/forms/chips การเคลื่อนไหว และสถานะ loading/empty/error/focus
9. แบ่งสิ่งที่จะทำเป็น “ปรับดีไซน์โดยใช้ข้อมูลเดิมได้”, “ต้องแก้การเชื่อมข้อมูลหรือเนื้อหาเดิม”, และ “ฟีเจอร์ใหม่ที่ต้องตัดสินใจเพิ่ม” พร้อมลำดับความสำคัญ

### หลักที่ต้องรักษา

- ใช้แบรนด์มงคลเวลา โลโก้จริง และแกนสี warm paper / lacquer red / jade / gold เป็นจุดตั้งต้น อนุญาตให้ปรับสัดส่วนสี ความเข้ม typography และ layout เพื่อให้ดีขึ้น แต่การเปลี่ยนชื่อหรือโลโก้ต้องเสนอแยก
- โทนอบอุ่น สุภาพ น่าเชื่อถือ มีความเป็นไทยและศรัทธาพอดี ใช้งานจริงได้ ไม่โอ้อวดผลการขอพร ไม่ขู่เรื่องเคราะห์ ไม่รับประกันโชคลาภหรือผลด้านสุขภาพ
- ทำ planner ให้เด่นและเข้าใจได้ทันที ขณะเดียวกันคนที่ต้องการค้นหาวัดอย่างเดียวต้องทำได้รวดเร็ว
- บอกให้ชัดว่าอะไรเป็นตัวอย่าง อะไรคำนวณตามข้อมูล และอะไรคือความเชื่อ ห้ามแปลงตัวอย่างแผนหน้า Home ให้ดูเป็นผลคำนวณสดหรือแผนเฉพาะบุคคล
- ห้ามอ้างว่ามี live traffic, เวลาเปิดที่ยืนยันวันนี้, กิจกรรมสด, รีวิวผู้ใช้, booking, account หรือฟีเจอร์อื่นที่เอกสารไม่ได้ยืนยัน หากอยากเสนอให้จัดเป็นฟีเจอร์ใหม่
- จำนวนวัดมาจากชุดข้อมูล ณ ช่วงเวลาหนึ่ง ไม่ใช่จำนวนปัจจุบันของทั้งประเทศที่ตรวจยืนยันสด หมวดสถานที่มีรายการซ้ำข้ามหมวด จึงห้ามบวกจำนวนทุกหมวดเป็นจำนวนสถานที่ไม่ซ้ำ
- ถ้าจะแก้ความซ้ำระหว่างสองหน้า ต้องรักษาทางเข้าไป planner, collections, directory, detail และ calendar ห้ามตัด route สำคัญเพียงเพื่อทำหน้าให้สั้น
- รักษาความอ่านง่ายภาษาไทย สระ/วรรณยุกต์ ชื่อวัดยาว และสถานะข้อมูลขาดหาย กรอบรูปของ cards ในกลุ่มเดียวกันต้องมีสัดส่วนคงที่ ปุ่มลบใน chip ต้องไม่ถูกชื่อยาวดันหาย
- แยกฟังก์ชันที่ต้องทำงานจริงออกจาก decoration อย่าเพิ่ม motion ที่กีดกันการอ่าน และต้องมี reduced-motion alternative
- คงช่องทางแก้ข้อมูลผ่าน CMS ห้ามเสนอ workflow ที่ต้อง hardcode สำเนาข้อมูลลงทุกหน้า
- ยังไม่ต้องเขียนโค้ดในคำตอบแรก ขอ critique, โครงหน้า, copy และข้อกำหนดดีไซน์ที่ตัดสินใจต่อได้ก่อน

### รูปแบบคำตอบ

เริ่มจากปัญหาสำคัญที่สุด 3-5 ข้อ แล้วตามด้วยตารางตัดสินใจราย section, แนวทางที่แนะนำ, โครงหน้า desktop/mobile และรายการงานเรียงลำดับ อย่าใช้คำว่า “premium”, “modern” หรือ “clean” โดยไม่บอกว่าจะแก้อะไรที่มองเห็นหรือใช้งานได้จริง

ใช้ข้อมูลปัจจุบันจากเอกสารเป็น baseline ไม่ต้องรักษาความผิดพลาดที่ถูกระบุไว้ แต่ต้องอธิบายเหตุผลเมื่อเปลี่ยน product decision หรือองค์ประกอบแบรนด์ที่มีอยู่
