# มงคลเวลา: Branding Guideline / CI สำหรับ redesign

ฉบับรวบรวมจากเว็บและ codebase วันที่ 20 กันยายน 2026

เอกสารนี้เป็น **working brand guide** ของระบบที่ใช้อยู่จริง ไม่ใช่คู่มือแบรนด์ที่เคยผ่านการอนุมัติเป็นเล่มมาก่อน ครอบคลุมแบรนด์ร่วมของทั้งเว็บไซต์ ส่วนวัด/การเดินทาง เครื่องมือเสริม และหลักการประยุกต์กับหน้าข้อมูล/Admin โดยแยกค่าที่มีจริงกับข้อเสนอแนะใหม่ไว้ชัดเจน

## 2. เหตุผลของ theme

พื้นกระดาษอุ่นสัมพันธ์กับคู่มือและบรรยากาศการเดินทาง แดงชาดเชื่อมกับงานรักและสีในวัด/ศาล เขียวหยกช่วยให้ palette เย็นลงและใช้สื่อข้อมูล ทองให้จังหวะแสงและความมงคล สีหมึกและพื้นเข้มช่วยให้อ่านชัดและเน้นเครื่องมือสำคัญ

นี่เป็น rationale ที่สอดคล้องกับทิศทางเดิมและหน้าที่ใช้อยู่ ไม่ใช่ผลวิจัยว่าสีเหล่านี้ทำให้ผู้ใช้เชื่อถือหรือกดปุ่มมากขึ้น

เอกลักษณ์ควรมาจากภาพจริง วัสดุสี น้ำเสียงภาษาไทย และจังหวะการจัดวาง ไม่จำเป็นต้องทำทุกพื้นที่ให้เป็นแดงทองหรือใส่ลายไทยทุกส่วน

ภาพตรามีองค์ประกอบทรงดอกบัว สถาปัตยกรรมคล้ายเจดีย์ เส้นโค้งสีทอง พื้นแดงและเขียว และประกายแสง คำบรรยายนี้อธิบายสิ่งที่เห็น ไม่ใช่การระบุความหมายทางศาสนาที่เจ้าของได้ประกาศไว้

กติกาสำหรับ redesign:

- ใช้ไฟล์จริงและรักษาสัดส่วน ห้ามพิมพ์ชื่อทับภาพแล้วอ้างว่าเป็น lockup เดิม
- ไม่บีบ ยืด ครอปตรา เปลี่ยนสี เติม glow หรือ shadow หนักเพิ่มบนตัวโลโก้
- Navbar ใช้ compact mark + wordmark ได้ ไม่จำเป็นต้องย่อ lockup ที่มีรายละเอียดมากจนอ่านไม่ออก
- Footer พื้นเข้มเหมาะกับ lockup ทองปัจจุบัน ให้ดู contrast จากภาพจริง
- ไม่กลับไปใช้ไอคอนเลข ๙ สีแดงจาก prototype เก่าแทนโลโก้ปัจจุบัน
- ใส่ alt ที่เหมาะสม: โลโก้ที่เป็นลิงก์หน้าแรกควรมีชื่อ/จุดหมาย; ภาพที่ตกแต่งซ้ำกับชื่อให้เป็น decorative

**ยังไม่พบข้อกำหนด clear space, minimum print size, CMYK/Pantone, monochrome/reversed logo หรือไฟล์ vector master ที่อนุมัติแล้วในหลักฐานที่ตรวจ** จึงไม่ควรสร้างตัวเลขเหล่านี้แล้วเรียกว่า official CI

ข้อเสนอแนะสำหรับงานดิจิทัลใหม่: เว้นพื้นที่รอบตราประมาณ 1/4 ของความสูง mark และพิสูจน์ความอ่านง่ายที่ขนาดใช้งานจริง ถือเป็นค่าเริ่มต้นสำหรับออกแบบ ไม่ใช่มาตรฐานเดิมที่บังคับใช้

## 5. Semantic colors และการไม่สับสนความหมาย

### ความมั่นใจข้อมูล

| ระดับ | สีที่ใช้ | ความหมาย |
| --- | --- | --- |
| ข้อมูลมั่นใจสูง | `#276A52` | สถานะข้อมูลที่พร้อมมากกว่าในโมเดลของเว็บ |
| ปานกลาง | `#C28D35` | ข้อมูลยังมีข้อจำกัด |
| ควรตรวจสอบก่อนไป | `#9B8578` | ต้องตรวจรายละเอียดเพิ่มเติม |

มีข้อความกำกับเสมอ สีนี้ไม่ใช่คะแนนศรัทธา ความแม่นยำของคำขอพร หรือเครื่องหมายสถานที่ผ่านการรับรอง

### หมวดเนื้อหา

- Popular: แดงชาด มีเลข ๙ ขนาดใหญ่เป็น watermark ใน card บางแบบ
- Sacred: card ขาวอุ่น ข้อมูล/ลิงก์เขียว
- Mu / สถานที่มงคล: พื้นทอง/กระดาษอุ่น ข้อความโทนน้ำตาลทอง
- Planner: พื้นเข้มและ CTA ทอง
- Thailand directory: คุมความหนาแน่น เน้น search/filter/table มากกว่าภาพและ decoration

### ป้ายภูมิภาค

CSS ของ region badges แบบเดิมมี palette แยก: เหนือ `#2F5F91`, กลาง `#8A5A19`, อีสาน `#6C3D7A`, ตะวันออก `#2A6F78`, ตะวันตก `#8B4B35`, ใต้ `#22694F` พร้อมพื้นและกรอบสีอ่อน

มี selectors ของ popular-directory variant ที่ override เป็นกลางแดง เหนือเขียว อีสานส้ม และภูมิภาคอื่นทอง จึง **ยังไม่ใช่ region-color mapping เดียวทั้งระบบ** ไม่ควรทำให้ทุก region เป็นเขียว หรือประกาศตารางใหม่ว่าคือมาตรฐานปัจจุบันโดยไม่ตรวจ consumers การปรับให้เป็น mapping กลางเป็นข้อเสนอแยกได้

### สถานะ UI

แดงแบรนด์ใช้กับ action ปกติอยู่แล้ว ข้อผิดพลาดจึงต้องมีข้อความ/สัญลักษณ์หรือ layout ช่วย ไม่สื่อด้วยแดงเพียงอย่างเดียว เช่นเดียวกับ selected/success ไม่ควรอาศัยเขียวล้วน

## 6. Typography ที่ใช้จริง

โหลด Google Fonts: **Noto Sans Thai**, **Prompt**, **IBM Plex Sans Thai**, **IBM Plex Mono**; English fallback ใน global token เป็น Helvetica/Arial

`--font-thai` หลัก = `"Noto Sans Thai", system-ui, sans-serif` ส่วน Home body และ header display บางส่วนประกาศ Prompt ก่อน IBM Plex Sans Thai/Noto Sans Thai

**ข้อสำคัญ:** Thai inheritance/cascade ทำให้หลาย node บน Home production ใช้ Noto Sans Thai แม้ body ประกาศ Prompt ไม่ควรสรุปจาก body ว่าทั้งหน้าคือ Prompt

ค่าที่วัดได้จริงบน Home production ที่ viewport 1280×720 ก่อนเปลี่ยนเนื้อหาตาม CMS (อ้างอิงเฉพาะ selectors/viewport นี้):

| Element | Font / weight | Size / line-height |
| --- | --- | --- |
| ชื่อแบรนด์ navbar | Prompt / 800 | 18.24px / 21.52px |
| Hero H1 | Noto Sans Thai / 900 | 102.4px / 100.35px |
| Hero copy | Noto Sans Thai / 500 | 19.2px / 34.18px |
| Section H2 | Noto Sans Thai / 800 | 40.96px / 42.60px |
| Intent title | Noto Sans Thai / 800 | 21.76px / 28.29px |
| Intent body | Noto Sans Thai / 400 | 16px / 27.52px |
| Body baseline | body declares Prompt stack / 400 | 16px / 26.4px |

ค่าที่วัดนี้เป็นหลักฐานของระบบเดิม ไม่ใช่ recommendation ให้ใช้ H1 line-height ต่ำกว่า 1 ต่อไปเสมอ โดยเฉพาะคำไทยหลายบรรทัดควรเผื่อสระและวรรณยุกต์

แนวทาง redesign:

- ให้ข้อความไทยอ่านง่ายก่อนรักษา silhouette ของ headline
- แยก display, heading, body, metadata และตัวเลขให้ชัด ใช้ weight/spacing ช่วย ไม่ขยายทุกตัวหนาเท่ากัน
- ลดจำนวน font roles ได้ถ้ามีเหตุผล แต่ระบุว่าเป็นข้อเสนอ ไม่ใช่ “แก้ให้ตรง CI เดิม”
- เลขไทยเหมาะกับ section markers และแนวคิด ๙ วัด; เวลา ระยะทางและข้อมูลใช้งานใช้เลขที่อ่านเทียบง่าย ปัจจุบันมีทั้งสองแบบ
- ชื่อวัดเป็นชื่อเฉพาะ ต้องมี wrapping/พื้นที่พอ ห้ามตัดจนเปลี่ยนความหมาย; chip ยาวอาจ ellipsis ได้เมื่อยังอ่านชื่อเต็มได้ด้วยวิธีอื่น
- ตัวอักษรอังกฤษเว้นช่องใน wordmark ได้ตาม asset แต่ไม่จำเป็นต้องถ่าย tracking นั้นไปลงข้อความไทยยาว
- ขนาดใหม่ควรกำหนดตามบทบาทและ breakpoints ให้แน่นอน พร้อมตรวจ Thai text fitting ไม่ใช้ความกว้างหน้าจอเป็นเหตุให้ตัวหนังสือแกว่งโดยไร้ขอบเขต

## 7. Layout, spacing, shape และ density

ค่าที่มีจริง:

- Global container token 1220px; Home ใช้ `min(1180px, calc(100% - 48px))`
- Home desktop intent grid 4 columns (6 รายการจึงเป็น 4+2), collections 3 columns, planner section 2 columns
- Home tablet ช่วง 721-1080px ปรับ hero/planner เป็น 1 column และ intent เป็น 2 columns
- Home ที่ 720px ลงมาใช้ 1 column; hero มี min-height 964px ใน CSS ปัจจุบัน ซึ่งเป็นประเด็นตรวจความยาวมือถือ ไม่ใช่ brand requirement
- Card padding ที่พบ 24px (intent), 28px (collection), Hub 26px; gap ของ grids มัก 16-24px
- Home section mobile padding ตัวอย่าง 66px แนวตั้ง; ความสูง section ควรขึ้นกับ content และงาน ไม่ใช่ใช้ค่าหนึ่งบังคับทุกหน้า
- Global radius token 8px, Home cards 14px, Hub cards 16px, today card 18px บน desktop / 16px บน mobile, pills 999px
- Home shadow variant `0 22px 58px rgba(39,29,20,.14)`; popular hero/card บางแบบมี red-tinted shadow

ค่ามุมโค้งที่ต่างกันเป็น variants ที่มีอยู่ ไม่ควร flatten ทุกอย่างเป็น 8px หรือ 16px โดยอัตโนมัติ ให้เสนอตามความหมายของ component และผลต่อภาพรวม

หลักร่วม: section เป็น full-width bands หรือ unframed content ที่มีแนว container ชัด ใช้ card สำหรับ repeated choices, สถานที่ หรือเครื่องมือที่ต้องมีกรอบ หลีกเลี่ยง card ซ้อน card และช่องว่างใหญ่ที่ไม่มีหน้าที่บนหน้าค้นหา/Planner

Home/Hub มีพื้นที่แสดงบุคลิกได้มากกว่า directory, detail form หรือ Admin ซึ่งต้องเน้นการอ่านเทียบและการทำงาน

## 8. ภาพถ่ายและ art direction

- Hero ใช้ภาพจิตรกรรม/บรรยากาศสถานที่เป็นพื้นเต็มพื้นที่ได้ พร้อม overlay พอให้อ่านชัด
- รูปใน cards/detail ต้องช่วยระบุสถานที่จริง ให้เห็นวัด สถาปัตยกรรม หรือจุดสักการะที่เกี่ยวข้อง
- ภาพบรรยากาศศาลเจ้าหรือพระพุทธรูปทั่วไปไม่ควรแอบใช้แทนรูปยืนยันสถานที่เฉพาะ
- รักษา focal point และตำแหน่ง crop ให้ดูรู้เรื่องบน desktop/mobile
- ภาพที่ไม่มีให้ใช้ fallback สีสงบของเว็บ `temple-placeholder-auspicious.png` โดยไม่สื่อว่าเป็นภาพถ่ายสถานที่นั้น
- กรอบภาพ cards ในกลุ่มเดียวกันต้องมีขนาด/สัดส่วนเดียวกัน ไม่ให้ intrinsic portrait dimensions ยืด card หรือดันรายละเอียด
- รักษาเครดิต/URL แหล่งภาพเมื่อระบบมีไว้ โลโก้จริงกับภาพท่องเที่ยวมีสิทธิ์ใช้งานคนละชุด การอยู่ในเว็บไซต์ไม่ได้ยืนยันสิทธิ์นำไปใช้ทุกช่องทาง
- Hero dark overlay, warm gradients และเส้นแสงเป็น treatment ที่มีอยู่ ใช้ได้อย่างพอดี ไม่จำเป็นต้องเพิ่มประกาย โลหะวาว หรือ pattern เพื่อให้ “ดูมงคล” มากขึ้น

## 9. Components และกติกาปฏิสัมพันธ์

| Component | เอกลักษณ์/พฤติกรรมที่ควรคง |
| --- | --- |
| Header | โลโก้ชัด ปุ่ม planner เด่น เมนู desktop เปิดแล้วเลื่อน pointer เข้าถึง panel ได้; mobile menu เลื่อนภายในได้ |
| Search | input สีอ่อน ไอคอนค้นหา label ที่อ่านด้วย screen reader ได้ ปุ่มแดง submit ปลายทางจริง |
| Primary CTA | คำกริยาชัด เช่น ค้นหา / วางแผนไหว้พระ; hierarchy ขึ้นกับพื้นอ่อน/เข้ม |
| Collection card | ทั้งใบมี affordance เป็นลิงก์ แยกหมวดด้วยเนื้อหาและสี ไม่ใช้ decoration แทน label |
| Temple card | รูปคงสัดส่วน ชื่อวัด จังหวัด/เขต ป้ายที่มีความหมาย และ action ที่เข้าถึงได้ |
| Intent card/chip | หัวเรื่องเข้าใจง่าย 6 เจตนา เป็นทางลัด ไม่ทำให้ดูเป็นผลทำนาย |
| Selected-place chip | มีลำดับ ชื่อ และปุ่มลบที่ไม่ถูกบีบหาย รองรับชื่อยาวและ tray scroll เดิม |
| Confidence | label + สี + คำอธิบายที่เข้าถึงได้ ไม่แสดงเหมือน rating หรือรีวิว |
| Tooltip | เปิดด้วย hover/focus และแตะบน touch ได้เมื่อเกี่ยวข้อง; ไม่ตัดข้อความ/ซ่อนหลัง container; มีวิธีปิด |
| Maps | แสดงข้อมูลสถานที่จริง ลิงก์รายละเอียด/นำทางและ close control ชัดเจน |
| Data table | คง dependent filters และ internal scroll; ความหนาแน่นต้องช่วย scan |
| Consent | surface สี paper, title/copy สุภาพ, ปุ่มยอมรับ/ปฏิเสธชัด; label ที่ตั้งไว้คือ “ยอมรับทั้งหมด” / “ปฏิเสธ” |
| Footer | พื้นเข้ม lockup ทอง กลุ่มเส้นทางและเครื่องมือ ไม่เพิ่มลิงก์ที่ไม่มีปลายทาง |

รูปแบบไอคอนส่วนใหญ่เป็น simple line icons และ glyphs ของ controls เช่น search/ลูกศร ไม่ใช้ emoji เป็นแกน navigation ของแบรนด์ หาก implementation ใหม่ใช้ icon library ให้ใช้ชุดเดียวที่เข้ากับงานเดิม ไม่ต้องวาดสัญลักษณ์มาตรฐานขึ้นใหม่

## 10. Motion

ค่าปัจจุบันจาก source:

- Hero text fade-up ประมาณ 720ms และมี stagger แยก eyebrow/headline/copy/search/links
- Section reveal ประมาณ 700ms, translateY 28px, delay ขั้นละ 55ms สูงสุด 220ms
- Card hover ยก 3-4px, transition บางแบบ 180ms
- Carousel เปลี่ยนภาพทุก 8 วินาที, transition ประมาณ 860ms; reduced motion ปิด auto advance
- มี scroll-linked movement ของพื้น hero/เส้นประกอบและ planner band

ความตั้งใจคือให้หน้าไหลและมีบรรยากาศ ไม่ทำให้รออ่าน ข้อกำหนดสำหรับ redesign คือข้อความไม่ fade ซ้ำจากการเปลี่ยนภาพ/โหลด CMS, refresh กลางหน้าต้องไม่ทิ้ง content ซ่อนอยู่, รองรับ reduced motion, ปุ่มและ search ใช้ได้ระหว่างการเคลื่อนไหว

ค่าเวลาหรือ ornament ลดได้เมื่อช่วยใช้งาน แต่การเอา animation ข้อความออกทั้งหมดไม่ใช่ความต้องการเดิมของเจ้าของ

## 11. น้ำเสียงและ microcopy

ใช้ภาษาพูดสุภาพที่กระชับ ช่วยตัดสินใจ ไม่เป็นราชการจนห่างเหิน และไม่ขายผลลัพธ์เหนือจริง

| ใช้ได้ | ควรหลีกเลี่ยง |
| --- | --- |
| วางแผนไหว้พระ / ค้นหาสถานที่ / เปิดแผนที่ | เรียกทรัพย์ทันใจ การันตีสมหวัง |
| นิยมสักการะเรื่อง... / ตามความเชื่อ | ไปแล้วสำเร็จแน่นอน |
| ข้อมูลควรตรวจสอบเพิ่มเติม | พิกัดเป๊ะทุกแห่ง / แม่นยำ 100% |
| ระยะเวลาโดยประมาณ / ตัวอย่างแผน | เร็วที่สุดแน่นอน / แผนเฉพาะคุณ ทั้งที่เป็น static |
| โปรดตรวจสอบเวลาเปิดก่อนเดินทาง | ใช้ข้อความยาวสอนการใช้งานทุกจุดจนกลบงานหลัก |

ชื่อ label ปัจจุบันที่ควรเริ่มจาก: วัดดังเสริมมงคล, วางแผนไหว้พระ, สายไหว้พระ ๙ วัด, วัดศักดิ์สิทธิ์, สถานที่มงคล, วัดทั่วประเทศไทย, วันพระ, เครื่องมือเสริม

URL `/temples/mu/` ยังอยู่แม้ label ปัจจุบันใช้ “สถานที่มงคล” มากกว่า “สายมู” ไม่ควรเปลี่ยน route เพียงเพราะเปลี่ยนคำบน UI

## 12. Accessibility และ responsive ที่ควรกำหนดในงานใหม่

ส่วนนี้เป็น acceptance criteria สำหรับ redesign ไม่ใช่การรับรองว่าทั้งเว็บปัจจุบันผ่านแล้ว:

- Contrast ตัวหนังสือและ controls ตามขนาดจริง; อย่าใช้ทองอ่อนเป็น body text บน cream
- Keyboard/focus-visible, label ของ form, heading hierarchy และลำดับอ่านต้องครบ
- ไม่พึ่งสีอย่างเดียวสำหรับ selected/error/confidence/region
- ปุ่มกดบน touch มีขนาดใช้งานเหมาะสม โดย 44px เป็นค่าเริ่มต้นที่ใช้อยู่ในหลาย control
- ภาษาไทยไม่ถูกตัดสระ/วรรณยุกต์ ชื่อยาวและ text zoom ไม่ทำให้ action หาย
- รูปมีกรอบคงที่ รองรับ image error และจองพื้นที่ก่อนภาพโหลด
- เมนู/tooltip ไม่พึ่ง hover อย่างเดียว และไม่ติดใต้ overflow/stacking ของ section
- รักษา consent decision และหลีกเลี่ยงบัง CTA สำคัญโดยไม่มีทางปิด/เลือก
- Motion มี reduced alternative และไม่ทำให้เนื้อหาหายเมื่อ JavaScript หรือข้อมูลมาช้า

## 14. สิ่งที่ควรรักษาและสิ่งที่ยังออกแบบใหม่ได้

รักษา: ชื่อและโลโก้, Thai-first, แกนสี, การให้ความสำคัญกับสถานที่/การเดินทาง, planner, ข้อมูลอย่างตรงไปตรงมา, การแยกความเชื่อกับข้อเท็จจริง, routes และพฤติกรรมใช้งาน

ปรับได้พร้อมเหตุผล: ลำดับ sections, copy, ขนาด hero, สัดส่วนภาพกับข้อความ, ขนาด/จำนวน cards, จังหวะช่องว่าง, type scale, ความแรง motion, CTA hierarchy และบทบาท Home เทียบกับ Hub

ต้องเสนอเป็นการเปลี่ยน brand/product เพิ่ม: โลโก้ใหม่ palette ใหม่ที่ละทิ้งแกนเดิม, การรับประกันผล, reviews/booking/account/events ใหม่ หรือการรวม/ลบ routes

## 15. ช่องว่างของ CI ปัจจุบัน

- ยังไม่มี master guide ที่ครอบคลุม clear space, print colors, logo variants และ governance อย่างเป็นทางการ
- Typography มีหลาย font stacks และ cascade overrides; ต้องเลือกให้ชัดว่าบทบาทใดใช้ฟอนต์ใด
- Radius, region colors และ CTA variants อยู่หลายระดับ ต้องประเมินตามบริบทก่อนรวมเป็นระบบ
- Motion และพื้นที่ hero อาจหนักกว่าที่บางงานต้องการ โดยเฉพาะ mobile
- ภาพจริงและ sample content ยังมีความพร้อมไม่สม่ำเสมอ
- CMS copy กับ initial HTML อาจไม่ตรงกัน ต้องกำหนด ownership ก่อนส่งต่อ implementation

ทั้งหมดนี้เป็นโจทย์ปรับปรุงที่ควรตัดสินใจจากหน้าจริง ไม่ใช่คำสั่งให้เปลี่ยนทุก variant ให้เหมือนกัน
