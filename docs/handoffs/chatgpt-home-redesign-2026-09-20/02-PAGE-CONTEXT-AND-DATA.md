# มงคลเวลา: บริบทหน้า Home, Temple Hub และที่มาของข้อมูล

วันที่ตรวจ: 20 กันยายน 2026 | ภาษา: ไทย | สถานะ: เอกสารส่งต่อเพื่อวิเคราะห์ redesign ไม่ใช่งานแก้เว็บไซต์

## 1. ต้องแยกสองหน้าก่อน

| หน้า | URL | บทบาทปัจจุบัน |
| --- | --- | --- |
| Home | https://mongkolwela.vercel.app/ | ประตูหลักของแบรนด์ แนะนำวิธีเริ่มต้นและจุดขายวางแผนไหว้พระ |
| Temple Hub / วัดดังเสริมมงคล | https://mongkolwela.vercel.app/temples/ | ศูนย์รวมหมวดสถานที่และทางเข้าเครื่องมือฝั่งวัด |

ภาพยาวที่เจ้าของแนบล่าสุดเป็น **Temple Hub**: มี breadcrumb หน้าแรก / วัดดังเสริมมงคล, หัวข้อใหญ่ “วัดดังเสริมมงคล”, collection cards 3 ใบ, เครื่องมือ 2 ช่อง, intent chips และแถบความมั่นใจข้อมูล ไม่ใช่ Home แม้สองหน้าจะใช้ภาพจิตรกรรมและชุดสีคล้ายกัน

ตรวจ production ทั้งสองหน้าและ source ปัจจุบันแล้ว บางเนื้อหามี CMS มาเปลี่ยนภายหลัง HTML เริ่มต้น จึงต้องอ่านข้อมูลหลังโหลดเสร็จด้วย

## 2. ที่มาที่ไปของ product

เว็บไซต์มีประวัติรวมเครื่องมือโหราศาสตร์ ปฏิทิน และการทำนาย แต่เจ้าของปรับทิศทางให้แกนหลักเป็น “วัด สถานที่ศักดิ์สิทธิ์ เสริมสิริมงคล และการเดินทางไปสถานที่จริง” หน้า Home จึงถูกปรับให้เริ่มจากความตั้งใจ การค้นหา และการวางแผน ไม่ใช่การเปิดไพ่หรือผูกดวง

เจ้าของเคยระบุชัดว่า **ให้ระบบจัดทริปเป็นจุดขายของเว็บ** จึงมีทั้ง CTA ใน navigation, hero shortcut และ section แสดงตัวอย่างแผน เครื่องมืออื่นยังมีอยู่ แต่เป็นส่วนรอง

แกนประสบการณ์คือ: ความตั้งใจหรือพื้นที่ที่จะไป → ค้นหา/เลือกหมวด → ดูสถานที่และข้อมูล → เลือกเข้าทริปหรือเปิดแผนที่ → เตรียมตัวเดินทาง

บุคลิกที่ต้องการคือคู่มือไทยร่วมสมัยที่อบอุ่น เคารพศรัทธา และใช้งานจริงได้ ความน่าเชื่อถือมาจากที่มาของข้อมูล พิกัด และการยอมรับเมื่อข้อมูลยังต้องตรวจสอบ ไม่ใช่การรับรองผลการขอพร

ความต้องการผู้ใช้ที่ระบบรองรับ:

- รู้ชื่อวัดหรือจังหวัดอยู่แล้วและต้องการค้นหาเร็ว
- มีเรื่องอยากเสริม เช่น งาน เงิน ความรัก สุขภาพ แต่ยังไม่รู้สถานที่
- อยากจัดทริป 3 / 5 / 9 แห่ง หรือมีสถานที่ในใจและอยากเรียงเส้นทาง
- ต้องการตรวจข้อมูลเข้าชม พิกัด วิธีเดินทาง หรือวันพระก่อนออกเดินทาง

ยังไม่มีข้อมูล analytics, conversion หรือผลทดสอบผู้ใช้แนบในงานนี้ จึงไม่ควรเรียกความต้องการเหล่านี้ว่าข้อค้นพบจาก user research

## 3. Home ประกอบด้วยอะไร

### 3.1 Shared header และ topbar

แถบเขียวด้านบนมีลิงก์คู่มือ ปฏิทินไทย รายละเอียดรายวัน และติดต่อ ตามด้วยโลโก้ เมนูวัดดังเสริมมงคล วันพระ เครื่องมือเสริม และ CTA “วางแผนไหว้พระ”

ฝั่งวัดมีทางเข้า planner, popular, sacred, mu และ directory; เครื่องมือเสริมรวมไพ่ยิปซีและเครื่องมือเดิมของเว็บ เมนูหลักรับข้อมูลจาก CMS ร่วมกับ shared shell ส่วนโลโก้และส่วนพื้นฐานมาจาก config

คำว่า “ติดต่อ” ที่เห็นปัจจุบันหลายจุดเป็นลิงก์ไป `#consult` ซึ่งอยู่ที่ footer ไม่ใช่หลักฐานว่ามี contact form หรือระบบนัดหมาย

### 3.2 Hero, search และข้อมูลประจำวัน

- พื้นหลัง carousel ภาพ 5 ภาพ: จิตรกรรมวัดไทย บรรยากาศวัด/ศาล พระพุทธรูป และธูปวง ใช้ overlay มืดเพื่ออ่านข้อความได้
- Eyebrow: “วัด · สถานที่ศักดิ์สิทธิ์ · เส้นทางมงคล”
- **ข้อความหลัง production CMS โหลดเสร็จขณะตรวจ: H1 “มงคลเวลา”**
- Copy หลัง CMS: “ค้นหาวัดและสถานที่ศักดิ์สิทธิ์สำหรับไหว้พระ ขอพร ทำบุญ และวางแผนเส้นทางมงคล ให้เหมาะกับสิ่งที่อยากเสริมในชีวิต”
- HTML เริ่มต้น/seed ในโค้ดใช้ “วางแผนไหว้พระ อย่างรอบคอบ” และข้อความอีกชุดหนึ่ง ความต่างนี้มีอยู่จริง ไม่ควรเลือก seed มาทับข้อมูลเผยแพร่เพราะคิดว่าใหม่กว่า
- ช่องค้นหา submit ไป `/temples/sacred/?q=...` จึงเป็นการเริ่มค้นหาในหมวด sacred ไม่ใช่ global search ที่ยืนยันว่าค้นครบทุกฐานข้อมูล
- ทางลัด: วางแผนไหว้พระ, เส้นทาง ๙ วัด, วัดทั่วประเทศไทย
- การ์ดข้อมูลประจำวันแสดงวันที่ไทยตาม Asia/Bangkok และลิงก์ปฏิทิน ข้อความ “ใช้ประกอบการวางแผนทำบุญและเริ่มสิ่งใหม่” เป็นข้อความทั่วไป ไม่ใช่คำแนะนำเฉพาะบุคคลหรือผลฤกษ์ที่คำนวณใหม่ทุกวัน

### 3.3 แถบข้อมูลสรุปสีเขียว

มีข้อความ 4 ชิ้น: “๙ เส้นทางไหว้พระยอดนิยม”, “๔๔,๗๐๔ วัดทั่วไทยพร้อมค้นหา”, “พิกัดสำหรับตรวจสอบเส้นทาง”, “วางแผน ๓ / ๕ / ๙ แห่ง”

ข้อความแถบนี้เป็น copy ที่กำหนดในหน้า ไม่ได้อ่านจำนวนจากฐานข้อมูลสด คำว่า “๙ เส้นทาง” ไม่ควรถูกตีความเป็นสถิติว่ามี 9 เส้นทางสำเร็จรูปที่ผ่านการยืนยัน

### 3.4 เลือกเรื่องที่ต้องการวางแผน

Intent cards 6 ใบพร้อมคำอธิบาย เป็นทางลัดค้นหา ไม่ใช่หมวดผลลัพธ์ที่สร้างด้วย AI ขณะคลิก:

| เจตนา | ปลายทาง Home |
| --- | --- |
| เสริมโชคลาภ เงินทอง | `/temples/sacred/?q=โชคลาภ` |
| การงาน ความก้าวหน้า | `/temples/sacred/?q=การงาน` |
| ความรัก เนื้อคู่ | `/temples/sacred/?q=ความรัก` |
| สุขภาพ และครอบครัว | `/temples/sacred/?q=สุขภาพ` |
| เริ่มต้นชีวิตใหม่ | `/temples/popular/?q=เริ่มต้น` |
| แก้ชง สะเดาะเคราะห์ | `/temples/mu/?q=แก้ชง` |

Intent เป็นภาษาเข้าถึงง่ายสำหรับพาคนไปค้นหา ไม่ใช่การรับรองว่าสถานที่แก้ปัญหาชีวิตเหล่านั้นได้

### 3.5 Planner spotlight

แถบพื้นเข้ม หัวข้อ “กำหนดเงื่อนไข แล้วจัดลำดับเส้นทาง” บอกว่าผู้ใช้เลือกจำนวนสถานที่ พื้นที่ เวลา และวัตถุประสงค์ได้ มี CTA ไป `/temples/planner/`

ด้านข้างเป็น **ตัวอย่างที่เขียนไว้ในหน้า**: วัดโพธิ์ 09:00 → วัดอรุณ 10:15 → วัดกัลยาณมิตร 11:20 และ “รวม ๑๑ กม.” ข้อความเกณฑ์การจัดลำดับก็เป็น sample copy ไม่ใช่ response จาก API ขณะดู Home

รูปตัวอย่างใช้ภาพประกอบทั่วไปบางภาพและ placeholder สำหรับวัดกัลยาณมิตร จึงไม่ควรอ้างว่าทุก thumbnail เป็นภาพยืนยันสถานที่นั้น ไม่ควรนำเวลา/ระยะทางตัวอย่างไปใช้เป็น travel advice ที่ตรวจสอบแล้ว

Planner จริงมีทั้งให้ระบบเลือกและเรียงทริป กับเลือกสถานที่เอง ข้อมูล catalog และการคำนวณมาจาก API อีกชุด ผลขึ้นกับพิกัด เงื่อนไข และข้อมูลเวลาเปิดที่มี ไม่ควรสรุปว่าเป็น live traffic หรือรับประกันเส้นทางเร็วที่สุด

### 3.6 หมวดหลักและฐานข้อมูลทั่วไทย

Collection cards 3 ใบ:

- **สายไหว้พระ ๙ วัด** `/temples/popular/`: ทางเข้ารายการวัดยอดนิยมเพื่อเลือกวางแผนต่อ
- **วัดศักดิ์สิทธิ์** `/temples/sacred/`: สถานที่ตามจังหวัด ภูมิภาคและวัตถุประสงค์
- **สถานที่มงคล** `/temples/mu/`: สถานที่สักการะ เสริมสิริมงคล แก้ชง และอธิษฐาน

มีลิงก์ “ดูทุกหมวด” ไป Temple Hub และแถบฐานข้อมูลทั่วไทยแสดง “๔๔,๗๐๕ วัด พร้อมค้นหา” พร้อมชื่อ filter ภาค จังหวัด อำเภอ/ตำบล นิกาย รหัสไปรษณีย์ ปุ่มพาไป `/temples/thailand/` ชื่อ filter บน Home เป็นข้อความแนะนำ ไม่ใช่ control ที่กรองข้อมูลได้ทันที

### 3.7 เครื่องมือเสริมและ footer

ลิงก์รอง: วันพระและปฏิทินไทย, คำเซียมซี, ไพ่ยิปซีรายวัน, อ่านลายมือ ตามด้วย footer แบรนด์และกลุ่มลิงก์ มี consent banner ตามสถานะการเลือกของผู้ใช้และ CMS จึงอาจไม่ปรากฏในภาพทุกครั้ง

Home ปัจจุบันไม่มี section คู่มือพร้อมภาพธูปขนาดใหญ่ที่เคยมีใน prototype เก่า อย่าใส่คืนโดยอ้างว่าเป็นของปัจจุบัน

## 4. Temple Hub ตามภาพแนบ

ลำดับปัจจุบัน:

1. Shared header และ hero ภาพจิตรกรรม: breadcrumb, “คู่มือวางแผนเดินทางมงคล”, H1 “วัดดังเสริมมงคล”, คำอธิบาย และ search
2. “เลือกจากหมวดหลัก”: popular / sacred / mu 3 cards โดยแยกแดง / ขาวอุ่นเขียว / ทองอ่อน
3. เครื่องมือ 2 ช่อง: วางแผนไหว้พระ 3/5/9 แห่ง และฐานข้อมูลวัดทั่วไทย
4. “เลือกเรื่องที่ต้องการวางแผน”: intent 6 chips
5. แถบข้อมูลตรงไปตรงมา: “ระบุเมื่อข้อมูลควรตรวจสอบเพิ่มเติม” พร้อมความมั่นใจ 3 ระดับ
6. แถบเครื่องมือเสริมและ footer

จำนวนที่เห็นทั้งบน Hub production และ local datasets ขณะตรวจคือ popular **243**, sacred **217**, mu **165** สถานที่ จำนวนมาจาก array length ตอนสร้างหน้า ไม่ใช่จำนวนไม่ซ้ำทั้งระบบ และไม่ยืนยันว่าจะปรับตามทุก Admin edit แบบสด

Hub search/intent ใช้ query `name=` ในขณะที่ Home ใช้ `q=` การ redesign ต้องรักษาการส่งค่าตามเส้นทางที่ระบบรองรับ ไม่เปลี่ยนชื่อ query จากภาพอย่างเดียว งานนี้ตรวจ markup/ปลายทาง ไม่ได้ทดสอบผลค้นหาทุกรูปแบบ

แถบ confidence เป็นคำอธิบายระดับความพร้อมของข้อมูลที่ช่วยวางแผน ไม่ใช่ rating ความศักดิ์สิทธิ์ และไม่ใช่การรับรองความถูกต้องของทุกฟิลด์

## 5. ข้อมูลมาจากไหน

| ข้อมูล | แหล่งหลักและการไหล | ข้อจำกัดที่มีผลต่อดีไซน์ |
| --- | --- | --- |
| โครงหน้า Home/Hub, intent, sample plan, CTA | Astro page + arrays/config ใน codebase | ส่วนมากเป็น editorial copy ไม่ใช่ข้อมูลสด |
| ข้อความ/ภาพ/เมนูที่ Admin แก้ | Published CMS → `/api/admin/content` → runtime patches | ข้อมูลที่เผยแพร่ปัจจุบันมีสิทธิ์เหนือ build seed; ต้องรองรับการโหลด/ผิดพลาด |
| รายการ popular, sacred, mu | ชุด research workbook → `build-temple-runtime-data.mjs` → JSON และข้อมูลแก้ไขจาก CMS ตามหน้า | หมวดซ้ำกันได้ รายการและความครบถ้วนไม่เท่ากัน |
| อันดับความนิยม | งานรวบรวมแหล่งอ้างอิง มี mentions, category/global rank, source keys/types และ Admin ordering | ไม่ใช่คะแนนรีวิวสด จำนวนผู้มาเยือนจริง หรืออันดับทางการ |
| ชุดทะเบียนวัดทั่วไทย | ไฟล์ที่เจ้าของให้ `Report_Temple 2.numbers` → `temples-thailand.json` → lightweight index/preview | snapshot ข้อมูล ไม่ได้ดึงทะเบียนปัจจุบันสดทุกครั้ง |
| ภาพสถานที่ | imageUrl/attribution ใน dataset, overrides และ Admin media | มีทั้ง Wikimedia และเว็บสถานที่/ท่องเที่ยว ต้องรักษาเครดิตตามสิทธิ์ของแต่ละภาพ |
| พิกัด | latitude/longitude, Plus Code และสถานะ/แหล่งอ้างอิง เช่น Nominatim/OpenStreetMap และ ArcGIS | ความมั่นใจต่างกัน; อย่าอ้างว่าพิกัดทั้งหมดได้รับการตรวจภาคสนาม |
| วิธีเดินทาง | structured travelDetail/routes และแหล่งเช่น Namtang GTFS ผ่าน Busmaps | ข้อมูลมีวันที่และ confidence; ไม่ใช่ตารางเดินรถสด |
| เวลาเปิด/ค่าใช้จ่าย/ช่องทางติดต่อ | ชุดข้อมูลเข้าชม, รายละเอียดแหล่งข้อมูล, CMS ตามรายการ | แสดงเท่าที่มีและให้ตรวจซ้ำ ไม่แต่งเวลาหรือราคา |
| วันที่บน Home | browser date จัดรูปแบบใน Asia/Bangkok | วันที่เปลี่ยนได้ แต่ copy ทั่วไปของการ์ดไม่ได้เปลี่ยนตามวันที่ |
| ปฏิทินไทย | โมดูลปฏิทินของเว็บและ provider | เป็นฟีเจอร์คนละส่วนจาก sample card หน้า Home; งานนี้ไม่ได้ audit ความถูกต้องทางปฏิทิน |
| ผลแผนจริง | `/api/temple-planner/data` และ `/api/temple-planner/plan` | ระยะ/เวลาเป็นค่าประมาณตาม engine และข้อมูลที่มี ไม่ใช่ผลจาก Home sample |

ชื่อ workbook ที่ generator ปัจจุบันอ้างถึง: `make-merit-9-temples-dataset.xlsx`, `sacred-temples-dataset.xlsx`, `mu-temples-dataset.xlsx` และ `temple-global-ranking-dataset.xlsx` ตัวอย่างแหล่งที่พบใน record ได้แก่บทความท่องเที่ยว Traveloka, Trip.com, ข้อมูลท่องเที่ยว และบริการเดินทาง ชื่อแหล่งเหล่านี้เป็นที่มาของข้อมูล ไม่ใช่พันธมิตรหรือ endorsement

ข้อความแหล่งข้อมูล directory ที่กำหนดให้ใช้คือ **“ระบบทะเบียนวัด สำนักงานพระพุทธศาสนาแห่งชาติ”** ใช้เฉพาะข้อมูลที่มาจากทะเบียน ไม่ขยายไปอ้างว่าข้อมูลขอพร/ภาพ/อันดับทั้งหมดมาจากหน่วยงานนี้

CMS production ใช้ Supabase เมื่อกำหนดไว้ หรือ authenticated GitHub ตาม configuration; valid published data เป็น source of truth ส่วน `live.json`/`default.json` ใน repository เป็น build/development seeds ไม่ใช่สิทธิ์ให้ทับการแก้เนื้อหาจริงของ Admin

## 6. ข้อเท็จจริงที่ควรแก้หรือระวังก่อน redesign

### ยืนยันจาก source/production

- **จำนวนวัดขัดกัน:** Home ticker 44,704 แต่ database CTA และ dataset 44,705; `rows.length` และ metadata ของไฟล์เท่ากับ 44,705 โดย metadata ระบุ generatedAt 2026-06-06 ควรใช้ค่าจากแหล่งเดียวและบอกบริบทว่าเป็นรายการในชุดข้อมูล
- **ทะเบียนทั่วไทยไม่มี latitude/longitude ใน 13 columns ที่ตรวจ:** มีชื่อ ประเภท นิกาย วันที่และที่อยู่ การอ้าง “พร้อมพิกัด” สำหรับทั้งหมด 44,705 รายการจึงกว้างกว่าหลักฐานของ dataset อย่าสับสนกับชุด curated temples ที่มีพิกัด
- **live hero ต่างจาก seed:** ต้องระบุว่าข้อความที่ออกแบบยึดฉบับใด และ publish ผ่านช่องทางเดิมอย่างมีเจตนา
- **แผนตัวอย่างไม่ใช่ผล API:** คง label ตัวอย่าง และปรับภาพ/เวลาให้มีที่มาหากต้องการยกระดับความน่าเชื่อถือ
- **`#consult` เป็น footer anchor:** การออกแบบปุ่มติดต่อใหม่ต้องมีปลายทางจริงก่อน
- **เนื้อหาซ้ำ Home กับ Hub:** มี intent, collections, planner และ directory เหมือนกัน แต่คนละลำดับ เป็นจุดพิจารณาด้าน IA ไม่ใช่เหตุผลให้ลบ route โดยอัตโนมัติ
- **เอกสารเก่าบางชุดล้าสมัย:** จำนวน 144 popular / 91 mu ใน Architecture เก่าไม่ตรง dataset ปัจจุบัน 243/165; อย่าใช้ข้อความในเอกสารเก่าแทนหลักฐานล่าสุด

### สมมติฐาน UX สำหรับให้ ChatGPT วิเคราะห์ ไม่ใช่ข้อสรุปจากผู้ใช้

- การให้เลือกจาก intent, collection, search และ planner หลายรอบอาจเพิ่มภาระตัดสินใจ
- Hero ขนาดใหญ่และการ์ดประจำวันอาจแย่งพื้นที่งานหลัก โดยเฉพาะบนมือถือ
- การใช้ภาพสถานที่จริงมากขึ้นอาจช่วยความเข้าใจและความน่าเชื่อถือ แต่ต้องไม่ใช้ภาพผิดสถานที่
- การจัดลำดับ CTA ใหม่อาจทำให้ planner ชัดขึ้น แต่ยังต้องคงทางค้นหาสำหรับคนที่ไม่ต้องการทริป
- ถ้าจะลดความยาวหน้า ให้พิจารณาความซ้ำและระยะห่างก่อนตัดข้อมูลช่วยตัดสินใจ

## 7. ข้อจำกัดที่ต้องส่งต่อให้ผู้ redesign

- รักษา routes, query/deep links, search/filter, navigation และทางไป detail/map/planner
- รักษา layout ข้อมูลที่ต้อง scroll ภายใน เช่น table, mobile navigation, selected places tray
- รูป portrait ต้องไม่ยืดกรอบ card; ชื่อวัดยาวต้องไม่ทำให้รายละเอียดหรือปุ่มหาย
- ประเมินเวลาเปิด/ข้อมูลขาดหาย/ไม่มีรูป/ไม่มีผลค้นหา/โหลดล้มเหลวเป็นส่วนหนึ่งของ design
- อย่าเอาอันดับวัด สี confidence และสีหมวดมาใช้สื่อความหมายเดียวกัน
- animation ข้อความ hero กับ carousel เป็นคนละระบบ ควรเริ่มข้อความเพียงครั้งเดียว ไม่ replay เมื่อเปลี่ยนภาพหรือรับ CMS content
- เว็บไซต์มี bot protection บางเครื่องมือเปิดไม่ได้ ไม่ควรลดมาตรการนี้เพื่อทำ redesign
- ใน worktree มีงานกิจกรรมวัดและ CMS freshness ที่ยังแก้อยู่ จึง **ไม่ยืนยัน** ว่าฟีเจอร์กิจกรรมเผยแพร่แล้ว และไม่รวมเป็น Home feature ปัจจุบัน
